## 真实文字对话

两组均可输入文字、多轮追问，Enter发送，Shift+Enter换行；中文输入法选词时不会误发。A组可向AI索要经后台原V0.6规则核对的高收益完整食谱，并点击对应回复的“一键填入食谱”，之后仍可修改。B组获得分析线索和反馈，服务端不返回完整食谱字段。A组每轮必须收到真实AI回应并确认查看后才可投喂；B组至少三个投喂轮次完成真实AI交流后可选择后续轮次自行决定。进入下一轮不自动请求AI。

前端和后端没有固定模拟回复或失败时模拟回退。错误明确显示，可重试上一条，失败请求不会冒充助手回复。对话与逐轮投喂、独立测试仍在浏览器保存，可由研究者导出；游戏尚无跨设备云端汇总。旧的模拟轮次数据保留其原始来源，不删除也不改写为真实AI。

## 服务端

使用原Supabase项目与DEEPSEEK_API_KEY，密钥不进入网页。/game/access签发两小时有效、仅限本会话和组别的游戏凭据；/game/chat验证后调用DeepSeek。凭据只保存在页面内存，不能读取研究数据，也不能调用旧报告操作。按开放参与要求，默认不设每日或单会话对话总次数上限；保留每会话每分钟8条的短时频率保护，连接签发每天400次。GAME_DAILY_CHAT_LIMIT和GAME_SESSION_CHAT_LIMIT仅在设为正整数时启用对应总量限制；0或未设置表示不启用。

公开入口不验证受邀资格，任何人都可领取游戏凭据；短时频率保护和跨域配置不能保证阻止脚本仿造实验请求。游戏凭据只限制可调用的功能，不代表真实参与者身份。旧报告AI默认单独关闭，需另行设置LEGACY_REPORT_AI_ENABLED=true才可调用。

游戏模型默认deepseek-flash，可用DEEPSEEK_MODEL覆盖；选择依据为当前DeepSeek官方API文档：https://api-docs.deepseek.com/ 。服务端将可见投喂记录、当前食谱及有长度限制的近期对话发给模型；A组另附当前规则核对过的高收益食谱候选，不发送规则公式、测试答案或认证凭据。游戏规则及后测仍在前端，正式施测前还需迁移。

历史研究数据读取与下载继续只允许已确认的huangrui1008@gmail.com及服务器名单。旧报告端点保持原有研究者认证，历史数据未迁移或覆盖。

## 十步流程（占位联调）

知情同意→AI素养→喂养游戏→独立测试→自我评估→操纵检验→代理感→图形找不同→心理所有权→学习获得感。原有游戏和独立测试保留，其他八环节均明确占位，不复用旧报告量表、不新增题目、选项、图形或计分规则。占位经过记placeholder_passed，responses/score为null；consent.obtained始终为false，不能当作已取得正式知情同意。流程结束记walkthrough_complete_with_placeholders。

新流程使用az-flow-v1-session-*键；az-preview-v06-session-*旧记录保留，研究者页面可读取和导出两类记录。记录新增flow_version、flow_current、flow_status、flow_steps与逐步时间；游戏与后测实际数据仍为rounds/tests。分组仍在打开入口时确定，AI仅在喂养阶段发送消息后调用，量表阶段和独立测试不显示AI与历史记录。后测成绩在全部流程走完后才显示。游戏数据仍只在本机保存，没有新增云端汇总。

## 本机真实AI预览

运行 `npm run preview`，在本机打开 `http://localhost:8775/?group=B`。本机服务器只监听127.0.0.1，只转发游戏连接和对话两个接口到原Supabase后台；后台继续验证游戏凭据并调用真实AI，模型密钥不进入本机或网页。运行预览不会部署代码或修改线上访问设置。

本机动态提供预览专用的config.js，仓库中的config.js保持原样。普通静态服务器不包含此连接通道。游戏记录仍在各自浏览器保存；此修复不增加远程研究数据收集。

A、B组的各入口均按视口宽度自动适配：仅在720px及以下、主指针为触控且不支持悬停时使用底部AI弹窗；电脑鼠标窗口即使较窄仍为内嵌对话。开关弹窗不发起AI调用、不清空聊天或草稿；关闭后恢复原页面位置。两组均按AI、食谱、确认投喂、动物增减排列。A组保留每轮真实AI咨询、完整食谱、快捷提问与一键填入，不提供自行投喂；B组至少三轮真实AI交流后可以选择自行投喂。

动物数量反馈：A/B共用约1.8秒的增减动画。新投喂结果在变化图案进入视野后播放；新增动物高亮弹出，实际减少的动物变为交叉眼后下沉淡出。结束时图案与数量一致，刷新、下一轮及AI弹窗不重播旧变化。尊重减少动态效果的系统偏好。数量到零时按before/after显示实际变化，原始rounds.delta规则结果保留，供核对。

## 最终食谱选择与展示（2026-11-23）

在原图形找不同之后、心理所有权之前，新增最终食谱选择与中性展示。保留原自我评估环节，当前共十二步，其余未定稿环节继续占位，不引入旧报告量表。正式施测尚需提供确认后的游戏版量表与同意材料。

十份食谱直接来自本会话的实际执行记录 `rounds[].x`，与 `aiRecipe` 建议分开；按轮次排列，不去重、不排序、不预选。确认保存 `final_recipe_round`、`final_recipe`（五种植物按既有 foods 顺序的份数）、`final_recipe_source`（本会话id、mode和R编号）、`final_recipe_confirmed_at`；候选项 `final_recipe_candidate_round` 随刷新保留。随后淡入及轻微缩放1.5秒，结束后可继续，卡片在心理所有权占位页仍可见。展示开始/结束时间分别记 `final_recipe_display_started_at` / `final_recipe_display_completed_at`，恢复时不重播已结束的动画。

进入选择、确认与展示时核对独立测试已完成及十轮实际记录；最终选择必须与本人的原轮次完全一致。异常时提示核对、允许导出原记录，不伪造配方。已有完成会话不重新开始或追补选择；旧进行中会话只补两个步骤定义，进入心理所有权缺少最终选择时可在已完成后测的前提下补选，不覆盖原投喂/测试记录。

JSON导出包含完整会话；CSV追加 `executed_recipes`、`final_recipe_round`、`final_recipe`、`final_recipe_source` 与确认/展示完成时间。父记录id/mode继续关联所有游戏、后测与问卷占位数据。数据仍仅保存于当前浏览器，研究者页仅显示本机或导入记录，尚无游戏数据云端汇总。发布前端不改变这一保存范围。


## 已完成流程重新进入（2026-11-23）

仅已完成且标为 is_test=true、walkthrough_complete_with_placeholders 的流程，在结束页提供“保留记录，重新开始”。点击时先把当前入口原始 JSON 原封不动保存到唯一的 az-flow-v1-session-archive-* 本机键并回读核对，然后创建新编号，从知情同意占位环节开始。新记录 restart_of 关联原编号；不继承旧轮次、对话、测试或最终食谱。当前入口的组别机制保持不变，其他入口记录不动。

研究者页既有读取前缀可直接识别归档，JSON导出保留全部旧记录与新记录。备份失败不开始；新流程保存失败时保留归档并恢复原记录。进行中、退出和正式完成记录不显示重新开始按钮，正常刷新仍续接当前任务，不自动清除记录。
